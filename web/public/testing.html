[02] — How it works / from empty sandbox to CI gate

Six steps, one command,
the same in CI.

The same path whether you start in the portal or the terminal. Each step produces something you can watch or keep.

01 · Pick a template

Choose your surface

playwright for browser, or android / mobile-test for the emulator. Chromium and the AVD are already baked.

02 · Write the test

Bring your spec

Drop in a @playwright/test suite or an adb/appium script — or paste it into the portal editor. No local setup.

03 · Run it

One command

pilldrops test ./suite.sh boots a fresh sandbox, installs deps, and launches the browser or the emulator.

04 · Watch it live

Stream as it goes

Exec output streams back in real time; the emulator run is screen-recorded, and the live report is served on a preview URL.

05 · Get the verdict

GREEN or RED, with proof

A clear verdict plus the evidence bundle: trace, video, screenshots, console logs and any files the test downloaded.

06 · Wire into CI

Gate your merges

The same one-liner drops into GitHub Actions. Block the merge on the verdict; every sandbox tears itself down.
