# Agent workstation documentation

An **agent workstation** is a sandbox whose template declares `kind: agent` — a persistent
machine running one of the agent CLIs under a supervisor, reachable by API, by chat, by
schedule, or from a link you send someone.

## The three ideas worth reading before the reference

**A turn is submitted, not awaited.** `POST …/agent/turns` returns `202` with a turn id. The turn
survives your connection: closing a laptop mid-task used to lose it, and the whole event-stream
design exists so it does not. Watch `…/agent/events` with a cursor rather than holding a request
open. The older blocking chat endpoint still works and carries a sunset date in its own
responses.

**Autonomy is a posture, chosen at launch.** Supervised asks before every action, Guided asks
before anything that changes things, Autonomous acts. Guided requires an approval gate that was
verified against the agent's real CLI — see the capability matrix — and when a gate cannot be
established, Guided is *not offered* rather than approximated. An agent that accepted the flag
and ignored it would run completely ungated while the interface claimed every action was
reviewed, which is worse than having no approvals feature at all.

**An unavailable capability says so.** Across all of this, a missing feature is reported with a
reason rather than hidden: `501` with an explanation is not the same as an empty list, `unknown`
is not the same as `no`, and a cost the agent never reported is absent rather than `0`. If
something here looks like it is missing, the response usually says why.

## Generated files

`api-reference.md`, `capability-matrix.md` and `limits.md` are generated by `cmd/gendocs` from
openapi.json, the launch manifest, and the constants the server enforces. Run `make docs` after
changing any of those; `make docs-check` and a Go test both fail when the checked-in output is
stale.

`tokens-and-scopes.md` and `webhook-verification.md` are written by hand, because they are
arguments rather than listings — a generator would turn "why `console` is not implied by `write`"
into a field table, which is the form in which nobody reads it. The code samples in the webhook
document are **extracted and executed** against a real signature by
`internal/extras/agent/webhook/docsamples_test.go`, so a sample that stops working fails the build.
